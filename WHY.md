# Por qué existe este proyecto

## Propósito

TournamentsManager es un laboratorio de ingeniería backend. El producto da un
contexto real al aprendizaje, pero la medida de éxito no es solo que “funcione”.
El proyecto debe permitir explicar por qué está diseñado así, qué alternativas se
descartaron, cómo se despliega y cómo se opera cuando algo falla.

## Resultados esperados

Al finalizar, el responsable del proyecto podrá:

- traducir necesidades de negocio a límites y modelos técnicos;
- diseñar una arquitectura simple con dependencias controladas;
- construir servicios en Go y persistencia en PostgreSQL;
- diseñar un entorno local comparable con producción;
- instrumentar, desplegar y operar el sistema;
- razonar sobre costes, seguridad, fiabilidad y portabilidad cloud;
- defender o revisar cada decisión importante con evidencia.

## No objetivos

- Acumular tecnologías para mostrar amplitud.
- Reproducir una arquitectura de gran empresa sin una necesidad real.
- Ocultar fundamentos detrás de automatizaciones.
- Diseñar una plataforma multi-cloud completa desde el primer día.
- Elegir el frontend, el dominio detallado o los requisitos sin el proceso de
  decisión acordado.

## Señales de calidad

Una fase se considera profesional cuando:

- tiene un objetivo verificable y criterios de salida;
- las decisiones importantes están aceptadas por el usuario y registradas;
- la documentación y el comportamiento observable coinciden;
- existen pruebas proporcionales al riesgo;
- el sistema puede diagnosticarse y recuperarse mediante procedimientos escritos;
- la complejidad introducida puede justificarse.
